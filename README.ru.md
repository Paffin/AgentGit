# AgentGit

**Контроль версий для людей и программирующих агентов.**

Поручайте агентам работу с явными границами, проверяйте результат и принимайте изменения по правилам репозитория.
AgentGit объединяет локальную CLI, собственный Web UI, инструменты агентов и CI в одном процессе ревью.

## Попробовать AgentGit

Установите опубликованную **v0.3.0-beta.7** для Linux (glibc) или macOS и откройте готовый деморепозиторий.
Rust, Node.js и отдельная настройка базы данных не нужны.

```sh
curl -fsSL https://raw.githubusercontent.com/Paffin/AgentGit/main/scripts/install.sh | sh -s -- --version 0.3.0-beta.7
export PATH="$HOME/.local/bin:$PATH"
ag-server dev --open
```

Установщик проверит контрольную сумму архива и сохранит программы в `~/.local/bin`. Сервер создаст деморепозиторий,
откроет браузер и выполнит вход. Если браузер не открылся, перейдите по ссылке из терминала.
Оставьте терминал работающим; **Ctrl-C** остановит сервер. После повторного запуска данные останутся в `./ag-dev-data`.

**В браузере:** откройте файл, нажмите **Edit**, предложите изменение, затем проверьте и примите его.
Правила деморепозитория защищают `SECURITY.md`: изменение этого файла покажет, как обязательное ревью блокирует принятие.

Демо доступно только с вашей машины и использует временные учётные данные. Для общего сервера есть
[руководство по развёртыванию](docs/operations/deployment.md). Windows, контейнеры, сборка из исходников,
другой каталог установки и ручная проверка архива описаны в [вариантах установки](docs/getting-started.md#install).
Документация в `docs/` — на английском.

## Первое изменение из терминала

Пока демосервер работает, откройте второй терминал в том же исходном каталоге:

```sh
export PATH="$HOME/.local/bin:$PATH"
ag login http://127.0.0.1:8080 --token-file ./ag-dev-data/dev/token
ag clone http://127.0.0.1:8080/demo/welcome
cd welcome
printf '\nA change from AgentGit.\n' >> README.md
ag snapshot -m "Update the readme"
ag push -t "Update the readme"
```

`ag push` напечатает ID предложения и опубликует изменение для ревью. Чтобы принять его, подставьте полученный ID:

```sh
ag remote integrate PROPOSAL_ID
ag pull
```

Если правила блокируют изменение, `ag remote explain PROPOSAL_ID` покажет, чего не хватает и какие команды помогут.
[Пошаговое руководство](docs/getting-started.md) объясняет ревью, доступ агентов и правила репозитория.

## Один процесс, четыре понятных ответа

**Snapshot** сохраняет вашу работу. **Proposal** публикует её для ревью. **Integration** принимает проверенный
результат в **stream** — общую ветку. У каждого предложения четыре независимых состояния:

| | Вопрос |
|---|---|
| **Mergeable** | Можно ли объединить изменение с текущей веткой? |
| **Validated** | Прошли ли доверенные проверки на том результате, который будет принят? |
| **Approved** | Одобрили ли нужные ревьюеры именно эту ревизию? |
| **Integrated** | Обновилась ли общая ветка? |

Успешные тесты не заменяют ревью. Одобрение старой ревизии не одобряет новую. Сервер проверяет правила
в той же транзакции, которая обновляет ветку: между проверкой и записью нельзя незаметно подменить результат.

![Экран ревью: изменённые файлы в основной области, действия и ревьюеры сбоку](docs/assets/ui-review-workspace.png)

*Это разрабатываемый интерфейс: упрощённый экран ревью выше ещё не входит в beta.7.
Опубликованные изменения и текущая разработка разделены в [changelog](CHANGELOG.md) и [roadmap](ROADMAP.md).*

У запусков агентов отдельные идентичности. Правила ветки задают обязательные проверки, ревьюеров, защищённые пути
и пределы самостоятельной работы агента. Решения записываются в журнал аудита. Ядро слияния и проверки правил
не вызывает языковую модель. [Основные понятия](docs/concepts.md) объясняют устройство,
[модель безопасности](docs/architecture/security.md) — границы доверия.

## Перенести существующий репозиторий

Создайте полный Git bundle и выберите **Repositories → Import from GitHub / GitLab** в Web UI.
Либо импортируйте его локально:

```sh
git bundle create repository.bundle --all
ag migrate repository.bundle ./project --namespace team/project
```

Импорт позволяет проверить соответствие веток и тегов и сохраняет исходный bundle. Git export оставляет путь назад.
Код и история переносятся; issues, комментарии, метаданные pull requests, LFS и настройка CI требуют отдельной работы.
Перед переносом команды прочитайте [руководство по миграции](docs/guides/migrate-from-git.md).

AgentGit — ранняя альтернатива для команд, которые пробуют работу агентов под правилами репозитория.
У GitHub и GitLab значительно шире возможности хостинга, управления проектами и опыт эксплуатации.
[Сравнение и компромиссы](docs/comparison.md).

## Статус и ограничения

**Ранняя публичная beta.** Текущий выпуск — [v0.3.0-beta.7](https://github.com/Paffin/AgentGit/releases/tag/v0.3.0-beta.7).
Стабильного выпуска и опубликованных пакетов в crates.io, npm и PyPI пока нет. Готовые архивы доступны для Linux
и macOS на x86_64 и ARM64; песочница worker работает только на Linux. Windows проверяется в CI,
но отдельный готовый архив для Windows ещё не выпускается.

**Перед обновлением сделайте резервную копию.** В beta.7 используется схема метаданных **8**.
Неопубликованная разработка использует схему **13**, которая добавляет назначенных ревьюеров и личные черновики ревью, комментариев и отдельных файлов, а также возобновляемый импорт issues.
Запуск сборки из разработки может обновить репозиторий; для возврата к старому бинарнику потребуется восстановить
копию до обновления. Подробнее: [резервное копирование](docs/operations/durability.md) и [история выпусков](CHANGELOG.md).

**Начните с данных, которые можно восстановить.** Внешняя проверка в production и независимый аудит безопасности
ещё впереди. Локальный режим доверяет тому, кто может записывать в каталог репозитория. Для недоверенных клиентов
нужен сервер, а для недоверенных проверок — [песочница worker](docs/guides/workers.md), а не `ag validate run`
в вашей оболочке. Сохраняйте резервные копии и Git-зеркало важных данных. В [roadmap](ROADMAP.md) перечислены
оставшиеся ограничения: перенос метаданных хостинга, LFS, submodules и проверки на реальных установках
и со вспомогательными технологиями.

## Сборка и участие в разработке

Для работы над CLI установите Rust 1.89 или новее и компилятор C:

```sh
git clone https://github.com/Paffin/AgentGit.git
cd AgentGit
cargo install --path crates/ag-cli --locked
```

[Contributing](CONTRIBUTING.md) описывает сборку сервера, Web UI, проверки и правила работы с репозиторием.
Устройство проекта раскрывают [обзор архитектуры](docs/architecture/overview.md),
[стратегия тестирования](docs/architecture/testing.md) и [архитектурные решения](docs/adr/README.md).
[Пример в английском README](README.md#build-and-contribute) показывает полный путь от отказа по правилам до принятия изменения;
его сценарий [`examples/quickstart.sh`](examples/quickstart.sh) выполняется в CI.
