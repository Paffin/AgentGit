# Реальная проверка AgentGit и проект CommentDoc

Дата: 21 октября 2026. Исходный commit AgentGit: `f87756d0505e94db2cee03455b9daf86e6723795`, версия `0.2.0-rc.2`. Проверка выполнена локально на macOS ARM64. Это отчёт о фактически выполненных проверках; прежние результаты CI не использованы как доказательство этого запуска.

## Результат

AgentGit собран и запущен. Через его CLI создан проект **CommentDoc**, проведён через snapshot → proposal → policy gates → signed validation → approval → integration. Затем проект отдельно опубликован по gRPC в настоящий ag-server, интегрирован на сервере, получен через pull и проверен через remote API и браузер. Готовый проект: [projects/commentdoc](../projects/commentdoc/README.md). Пример результата: [API.md](../projects/commentdoc/docs/API.md).

Работающий UI: http://127.0.0.1:18080. Проект: http://127.0.0.1:18080/repos/demo/commentdoc. Сервер слушает только loopback и использует SQLite и файловое хранилище. UI отдаётся самим ag-server из собранного `apps/web/dist`.

Для пользователя создан `user:mkiktev` с административными правами и токеном на 24 часа с момента выдачи. Вход: поле Access token → Sign in → Continue. Токен находится в `.runtime/ui-token.txt` с правами `0600`; секреты не включены в отчёт. Данные сервера: `.runtime/server-data`; технические учётные данные: `.runtime/credentials.json`. Сервер оставлен работающим. Повторный запуск после его остановки: `python3 reports/scripts/serve_local.py` из корня проекта.

## Что реализовано

CommentDoc — самостоятельный Python CLI без сторонних зависимостей. Он рекурсивно обрабатывает `.py`, разбирает AST без импорта/исполнения исходников и генерирует Markdown:

- docstring модуля, публичных функций, классов и методов;
- обычные последовательные комментарии `#` перед объявлением, когда docstring отсутствует;
- сигнатуры, аннотации, async-функции, имена вложенных методов, относительный файл и номер строки;
- Unicode, стабильный порядок и воспроизводимый результат на одной версии Python;
- `--check` для обнаружения отсутствующей/устаревшей документации без её перезаписи;
- атомарная запись и сохранение прежнего Markdown при синтаксической ошибке.

Пример `examples/billing.py` содержит реальный расчёт суммы и комментарии на русском. Сгенерирована документация `docs/API.md`. Приватные имена исключаются. Проект ограничен Python: это конкретная реализация сценария, а не универсальный документатор всех языков. Разрешение импортов/наследования, поля классов и комментарии внутри тел функций не реализованы. Docstring трактуется как Markdown; универсальное экранирование произвольного содержимого не реализовано. Версию Python в CI следует фиксировать из-за форматирования `ast.unparse`.

Запуск из корня AgentGit:

```sh
python3 projects/commentdoc/commentdoc.py projects/commentdoc/examples -o projects/commentdoc/docs/API.md
python3 projects/commentdoc/commentdoc.py projects/commentdoc/examples -o projects/commentdoc/docs/API.md --check
python3 -m unittest discover -s projects/commentdoc/tests -v
```

### Реалистичные положительные и отрицательные сценарии

1. Штатный quickstart действительно меняет файлы, регистрирует двух агентов, создаёт отдельные workspace и проверяет конфликт одновременных правок одной строки. Конфликт возвращает exit 4; после ручного разрешения и повторных проверок изменение интегрируется.
2. Проверены эксклюзивный lease и fencing token, provenance, подписанные результаты проверок точного дерева, блокировка до выполнения требований, автономное изменение разрешённых путей и запрет интеграции кода агентом вне разрешённой области.
3. В CommentDoc сначала записаны требования и тесты без реализации. Затем создан агент `commentdoc-builder`, которым опубликована реализация. Попытка интеграции самим агентом отвергнута с exit 4. Интеграция человеком до выполнения условий блокировалась с exit 3. Проверка кандидата в отдельном каталоге запускала реальные `unittest` и проверку актуальности `API.md`.
4. Даже после успешных тестов, но без approval, интеграция оставалась заблокированной. После approval тестовой роли изменение вошло в `main`. Сохранены идентификаторы proposal и run в [commentdoc-receipt.json](commentdoc-receipt.json). Локальная история и ключи остаются в `projects/commentdoc/.ag` и исключены из внешнего Git.
5. Локальные `user:developer`, `user:reviewer-test`, `agent:*`, `service:ci` — роли, которыми управляла одна сессия. Это доказательство поведения политики, **не независимое человеческое ревью или разделение доверия**. Ядро AgentGit само код не сочиняло: реализация написана текущей сессией Codex и проведена через операции AgentGit.
6. На сервере проект отдельно опубликован администратором в `demo/commentdoc` с политикой по умолчанию. Серверная публикация проверяет транспорт и доступность результата, а строгая политика CommentDoc проверялась в локальном репозитории. Эти два разных прогона не следует смешивать.
7. Серверные 52 проверки включают ошибочные/отсутствующие токены, создание дубликата репозитория, запрет интеграции writer, разрешение integrator, передачу объектов, два клиента, чтение истории/файлов и изменение Prometheus-метрик от реальных запросов HTTP и gRPC.
8. Браузерный набор включает вход/выход, роли read-only, четыре состояния proposal, потерю актуальности approval, отзыв доступа, retry при 429, offline/reconnect, SSE, diff/blame/history, XSS/CSP-поведение, клавиатуру, светлую/тёмную темы, axe и адаптивность. Это автоматизированные браузерные сценарии с реальным сервером; тестовый IdP и CI-помощник набора не являются настоящими внешним IdP и CI-инфраструктурой.
9. Генератор проверен на изменении исходника после генерации (`--check` возвращает 1 и сохраняет файл), синтаксической ошибке (exit 2 и сохранение прежнего документа), несуществующем/пустом каталоге, Unicode, async-методе, приватной функции и повторной генерации одинаковых байтов.

## Найденные ограничения и проблемы запуска

Критических отказов в выполненных сценариях не обнаружено. Это не утверждение об отсутствии дефектов во всём продукте.

- На машине отсутствовал Rust. Он установлен из rustup локально в `.runtime`, без изменения глобального PATH. Установлены npm-зависимости и Chromium. Сборочные каталоги и секреты исключены из Git.
- Системный `/usr/bin/python3` — 3.9; штатный `scripts/e2e_smoke.py` использует синтаксис типов Python 3.10+. На 3.9 он падает до проверки сервера с `TypeError` для `str | None`. Проверка успешно выполнена на установленном Python 3.13. Это ограничение окружения/предпосылок скрипта; исходный скрипт не менялся.
- Начальный Go-прогон без пути к серверу пропускал интеграции. Поэтому выполнен отдельный окончательный прогон с `AG_SERVER_BIN`, и только его JSON-результаты использованы в таблице.
- Ограниченная песочница среды запрещала сеть и открытие TCP-портов; необходимые команды повторены с разрешением. Ошибки DNS/EPERM первоначальных попыток не считаются дефектами AgentGit.
- Вход токеном показывает карточку учётной записи и требует явного Continue. В собственной браузерной проверке это учтено. Постоянные соединения SSE требуют ожидания готового элемента страницы, а не бесконечного ожидания полного отсутствия сети.

## Что не подтверждено этим запуском

- Настоящий Keycloak: 6 браузерных и 3 Rust-проверки пропущены. Браузерный тестовый IdP покрывает механику, но не заменяет этот прогон.
- Живая LLM и автономный model-mode: 5 Go-тестов пропущены, ключи/модель не настраивались. Из этого запуска не следует, что оркестратор самостоятельно написал CommentDoc по текстовой задаче.
- PostgreSQL/S3/HA, отказоустойчивость нескольких реплик, TLS и внешние ingress не поднимались; фактическое хранилище этого сервера SQLite + fs.
- Docker/Podman OCI-изоляция и Linux namespaces не квалифицированы. На macOS часть execution-plane проверок использует разрешённый тестами limits-only fallback; OCI-ветки без `AG_OCI_IMAGE` могут выйти без выполнения. Успешный общий Rust-набор не доказывает контейнерную изоляцию.
- Три измерительных Rust-теста проигнорированы штатно; нагрузка, долговременная стабильность и пределы производительности не измерялись.
- Firefox/WebKit, Windows/Linux, screen reader, Kubernetes, публикация релиза и production-развёртывание в этом запуске не проверялись.

## Воспроизведение и сохранённое состояние

Сценарии проверки: [commentdoc_workflow.py](scripts/commentdoc_workflow.py), [remote_validation.py](scripts/remote_validation.py), [remote_finish.py](scripts/remote_finish.py). Первый намеренно откажется перезаписывать существующий `.ag`; remote-сценарий создания рассчитан на новый сервер и не является идемпотентным. `remote_validation.py --verify` проверяет сохранённое состояние после перезапуска. Он требует Python 3.10+ и локальные приватные `.runtime`-артефакты текущего запуска.

AgentGit core, UI и SDK не изменялись. Добавлены сам проект, этот отчёт, доказательства/сценарии и исключение `.runtime/` в `.gitignore`. Публикации в удалённый Git, релизов и push не выполнялось.
